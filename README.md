# Forbes для CRMP — Vercel

Готовый русскоязычный адаптивный рейтинг. Node.js API подключается к вашей существующей MySQL/MariaDB только на чтение. SQL-дамп не надо загружать на Vercel.

## Развёртывание
1. Проект уже загружен в этот репозиторий. При необходимости скачайте его через Code → Download ZIP.
2. На https://vercel.com выберите Add New → Project → этот репозиторий. Framework Preset: Other. Корень проекта — папка с package.json. Output Directory: public. Install Command: npm install. Build Command оставьте пустым (vercel.json уже настроен).
3. Добавьте Environment Variables из .env.example: MYSQL_HOST, MYSQL_PORT, MYSQL_USER, MYSQL_PASSWORD, MYSQL_DATABASE. Пароль вводите только в настройках Vercel. MYSQL_HOST — адрес сервера БД, не localhost и не адрес сайта. Переменные не должны иметь префикс NEXT_PUBLIC_.
4. MYSQL_SSL=true включает TLS с проверкой сертификата. Для БД без TLS требуется MYSQL_SSL=false. Предпочтительно настроить защищённое соединение на стороне хостинга.
5. Предоставьте отдельному пользователю только SELECT на accounts, bank_accounts, business, fuel_stations, houses и ownable_cars. Не используйте root. Хостинг MySQL должен разрешать внешние соединения из Vercel; для закрытой сети понадобится отдельное сетевое решение/фиксированный исходящий IP.
6. Нажмите Deploy. После изменения переменных сделайте Redeploy. Если живое подключение недоступно, сайт показывает пустой резервный снимок и сообщение об ошибке подключения.

Для локального запуска: npm install, скопируйте .env.example в .env.local и заполните значения, затем npx vercel dev. Открытие index.html как файла не поддерживает API; статический снимок можно просмотреть через любой HTTP-сервер из папки public.

## Как считается капитал
По умолчанию: accounts.money + accounts.bank + SUM(bank_accounts.balance WHERE uid=accounts.id) + кассы принадлежащих игроку business и fuel_stations. Каждая дочерняя таблица сначала агрегируется: соединения не умножают суммы из-за нескольких объектов у одного владельца. Все игроки доступны с поиском, пагинацией, сортировкой и разбивкой капитала. Места всегда обозначают место по общему капиталу.

BANK_MODE=both — обе банковские системы (по умолчанию); accounts — только accounts.bank; separate — только bank_accounts. Дамп не содержит кода игрового мода: нельзя доказать, что банковские системы не дублируются. Проверьте конкретного игрока в игре и выберите правильный режим до публикации. Снимок всегда использует both; эти переменные применяются только к живой БД.

INCLUDE_BUSINESS_BALANCES=false исключает кассы из капитала. EXCLUDE_ADMINS=true убирает аккаунты с admin != 0 (только в живой БД). Владелец объекта определяется по owner_id; не принадлежащие игрокам объекты не учитываются.

Дома, машины, бизнесы отображаются количеством. houses.price показана отдельно, без включения в капитал. Для машин в ownable_cars нет цены: оценка не выдумывается.

Дополнительно найдены accounts.bitcoin, rub, donate_current, coins, phone_balance, wage, family.money, auction_bid_reservations.amount, miner_pending_wages.amount, return_money.money. Они не включены в личный капитал: иные валюты, общие средства, резервы или ожидаемые выплаты требуют правил игрового мода. Таблицы money_log, bank_audit_log и другие логи — история, их нельзя суммировать как текущий баланс.

## Данные и обновление
public/snapshot.json — пустой шаблон. Игровые профили и балансы из загруженного SQL не публикуются в открытом репозитории. Для реального рейтинга настройте живую MySQL в Vercel. Пароли, соли, email, IP, PIN и служебные поля API не экспортирует. Исходный SQL в репозиторий не включён.

Обновление в браузере каждые 60 секунд; CDN-кэш API 30 секунд со stale-while-revalidate 30 секунд. Это периодическая синхронизация, не поток в реальном времени. При ошибке БД показывается явно подписанный резервный снимок (пустой шаблон). Изменение схемы/названий таблиц требует обновления lib/query.js. Интерфейс не редактирует игровые данные.

Проверка: npm test. Доступ к вашей живой БД и публикация в вашем аккаунте Vercel требуют ваших настроек и здесь не проверены.
